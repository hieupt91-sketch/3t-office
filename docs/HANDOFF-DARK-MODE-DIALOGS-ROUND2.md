## FINDINGS (real screenshots taken before fixing, not assumed)

Opened Dark Mode via the real toggle and captured every dialog listed in the task brief. Two distinct problems found:

1. **Sheet Format Cells dialog was entirely unaffected by Dark Mode** — it builds its own dialog chrome directly in `apps/sheet/format-cells-dialog.js` (background/border/text colors hardcoded as hex, e.g. `background: #ffffff`) instead of relying on the shared `.vno-dialog-box` chrome other dialogs use. Screenshot: `docs/screenshots/before-sheet-format-cells.png` shows a fully light dialog while the rest of the app is dark.
2. **Most other dialogs had correctly-dark chrome (background/labels) but white input/select fields** — Conditional Formatting, Pivot Table, Name Manager, Watermark, etc. use the shared `.vno-dialog-box`, whose Dark Mode tokens (from the prior task) covered the dialog surface but not `<input>`/`<select>`/`<textarea>` elements specifically, which keep the browser's native white background unless explicitly styled. Screenshots `before-sheet-cond-formatting.png`, `before-sheet-pivot-table.png`, `before-writer-watermark.png` show dark labels next to bright-white input boxes — readable but visually jarring, an inconsistent "light hole" look, not a genuine contrast/legibility failure (dark text on white is still readable) but clearly not finished Dark Mode coverage.

Slides Theme Gallery, Slide Master, and Transitions dialogs, plus Writer Mail Merge's CSV textarea, were already correctly dark before this task — not every dialog needed a fix.

## IMPLEMENTATION SUMMARY

1. `platform/ui-kit/ui-kit.css` — added a broad, cascading rule targeting every text/select/textarea input anywhere inside `.vno-dialog-box` (explicitly excluding checkbox/radio/color/range, which need different treatment and aren't text-legibility risks) to use `--vno-bg-surface`/`--vno-text-primary`/`--vno-border-default`. This single change fixes every dialog built on the shared chrome in one place, rather than patching each dialog file individually.
2. `apps/sheet/sheet.css` — converted the remaining hardcoded hex colors in the Sheet-specific rule-dialog styles (labels, `.vno-rule-range`, `.vno-data-preview`, Format Cells tabs/category list/negative-number list, Pivot Table field rows, Name Manager list/form) to the same tokens, plus added `fieldset`/`legend` styling that Paste Special's radio-group markup needed.
3. `apps/sheet/format-cells-dialog.js` — replaced every hardcoded hex color in this dialog's own inline-styled markup (it doesn't use `_createSheetDialog()`) with the equivalent CSS custom properties, since rule #1 above can't reach inline `style="..."` attributes.

**Known, accepted limitation**: `input[type="range"]` (e.g. Watermark's opacity slider) is intentionally excluded from the broad selector — native range-input track/thumb styling doesn't respond to a plain `background-color` the same way across browsers and needs vendor-prefixed `::-webkit-slider-runnable-track`/`::-moz-range-track` rules to restyle properly, which was out of scope for this pass. It stays visually white in Dark Mode; this is a minor cosmetic gap (no text/contrast problem, since a slider carries no text), not a functional or accessibility regression, and is flagged rather than silently left unmentioned.

## RISKS
