## Q50 continuation: return focus to keyboard-invoked ribbon command

### Objective
When the user Tabs to a command in the ribbon, activates it, and closes its dialog, keep focus on that command. Dialogs opened from document focus continue returning focus to the editor.

### Current capability
Three CDP cases reproduced the exception: Tab reached `writer.reference.captionInsert`, `sheet.data.validation`, and `slides.insert.dateTime`; activating each real ribbon button opened the dialog, and Escape left focus on a `DIV` in the editor. The global Enter guard intercepts Enter before ribbon-button handlers run. When the button is activated programmatically in the focused state, each close handler restores the captured invoker, but the focus guard and CommandBus schedule `restoreEditorFocus()` and override it after the dialog closes.

### Files/modules
- `platform/shell/focus-manager.js`: allow Enter activation on ribbon command buttons, track keyboard-invoked dialogs, and keep the captured ribbon command focused after close.
- `platform/ui-kit/components.js`: mark a zero-detail ribbon command activation as keyboard initiated.
- `platform/commands/command-bus.js`: preserve the tracked keyboard dialog trigger when deferred command focus restoration runs.
- `tests/live/cdp/q50-ribbon-focus-return.desktop.mjs`: retain the three-app Tab/activate/Escape regression and before/after screenshots.
- `docs/UI-SWEEP-PART5-22-10.md`, `09-templates/AGENT-HANDOFF.md`: record evidence and remaining sweep items.

### Dependencies and risk
No new dependency. Shared focus behavior affects all apps and dialog types; preserve current editor fallback whenever focus was not restored to a live ribbon command. A stale/detached ribbon element must never retain focus.

### Test plan
Run the CDP case before the fix (Enter activation/dialog focus failed in all three apps), then after the fix (3/3 actual Tab+Enter/Escape flows), capture and inspect all six 1366×768 screenshots. Run `npm test`, i18n parity, checklist evidence audit, and focused pytest. No checklist generator is needed unless command definitions or localized strings change.
